# 城市空气质量看板 · 数据集定义

> 版本：v1.1（2026-10-19）
> 变更记录：v1.0 为小时粒度（105,120 行）；**v1.1 按需求变更为天粒度（4,380 行）**。原"超过十万行"的量级要求随粒度变更不再适用；若后续需要恢复大表，可改为小时数据入库、看板端按天聚合（见第 1 节备注）。

## 2. 城市选取（12 城）及理由

选取遵循四个维度的代表性，确保看板上三种图表都有"故事可讲"：

1. **区域均衡**：覆盖华北、东北、中原、华东、华南、西南、西北七大地理区；
2. **污染类型梯度**：燃煤采暖型、沙尘型、臭氧型、盆地静稳型、沿海清洁型全覆盖；
3. **AQI 全梯度**：从"常年优"（海口、深圳）到"冬季重度污染"（石家庄、西安），保证排行榜首尾分明、颜色分段齐全；
4. **首要污染物多样性**：PM2.5、PM10、O3 在不同城市/季节成为首要污染物，让概览卡的主要污染物字段有变化。

|---|---|---|---|---|

**AQI 梯度校验**：海口/深圳（优/良）→ 广州/上海/杭州（良，夏季 O3 偏高）→ 北京/郑州/成都（良~轻度）→ 西安/哈尔滨（冬季中度）→ 石家庄（冬季重度）。六个 AQI 等级全部可被覆盖。

**首要污染物校验**：冬季北方城市 → PM2.5；春季兰州 → PM10；夏半年南/东部城市 → O3；AQI≤50 时 → 无首要污染物。

## 4. AQI 口径（依据 HJ 633-2012，日报口径）

### 4.1 计算方法

```
IAQI_p = (IAQI_Hi − IAQI_Lo) / (BP_Hi − BP_Lo) × (C_p − BP_Lo) + IAQI_Lo
AQI    = max(IAQI_PM2.5, IAQI_PM10, IAQI_SO2, IAQI_NO2, IAQI_CO, IAQI_O3)
```

- 浓度 `C_p` 取各污染物的**日均值统计量**：PM2.5/PM10/SO2/NO2 为 24 小时均值，CO 为 24 小时均值，O3 为 8 小时滑动均值的当日最大值；
- **首要污染物**：IAQI 最大的污染物（IAQI > 50 时才计入；AQI ≤ 50 时记为"无"）；
- 超出最高分段的浓度按 IAQI = 500 封顶。

### 4.2 日均浓度 IAQI 分段表

| IAQI | PM2.5(24h) | PM10(24h) | SO2(24h) | NO2(24h) | CO(24h, mg/m³) | O3(8h) |
|---|---|---|---|---|---|---|
| 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| 50 | 35 | 50 | 50 | 40 | 2 | 100 |
| 100 | 75 | 150 | 150 | 80 | 4 | 160 |
| 150 | 115 | 250 | 475 | 180 | 14 | 215 |
| 200 | 150 | 350 | 800 | 280 | 24 | 265 |
| 300 | 250 | 420 | 1600 | 565 | 36 | 800 |
| 400 | 350 | 500 | 2100 | 750 | 48 | — |
| 500 | 500 | 600 | 2620 | 940 | 60 | — |

（单位 μg/m³，CO 为 mg/m³。）

## 5. 表结构草案（任务 2 落地为 init.sql 的依据）

### 5.1 `city`（12 行）

| 列 | 类型 | 说明 |
|---|---|---|
| id | INT PK AUTO_INCREMENT | 城市编号 1~12 |
| city_name | VARCHAR(20) NOT NULL | 城市名 |
| province | VARCHAR(20) | 省份 |
| region | VARCHAR(20) | 所属地理区（华北/东北/中原/华东/华南/西南/西北） |
| longitude | DECIMAL(5,2) | 经度（预留地图扩展） |
| latitude | DECIMAL(4,2) | 纬度（预留地图扩展） |

### 5.2 `air_quality`（4,380 行）

| 列 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AUTO_INCREMENT | 主键 |
| city_id | INT NOT NULL | 外键 → city.id |
| monitor_date | DATE NOT NULL | 监测日期 |
| pm25 | SMALLINT UNSIGNED | 24h 均值，μg/m³ |
| pm10 | SMALLINT UNSIGNED | 24h 均值，μg/m³ |
| so2 | SMALLINT UNSIGNED | 24h 均值，μg/m³ |
| no2 | SMALLINT UNSIGNED | 24h 均值，μg/m³ |
| co | DECIMAL(4,1) | 24h 均值，mg/m³ |
| o3 | SMALLINT UNSIGNED | 8h 滑动均值当日最大，μg/m³ |
| aqi | SMALLINT UNSIGNED | 日报 AQI（按 4.2 计算） |
| primary_pollutant | VARCHAR(8) | PM2.5/PM10/SO2/NO2/CO/O3；AQI≤50 时为 NULL（无） |
| level | TINYINT UNSIGNED | 1~6，对应 4.3 等级 |

**唯一约束与索引**：

| 索引 | 服务的查询 |
|---|---|
| `uk_city_date (city_id, monitor_date)` UNIQUE | 防重复导入；趋势图：某城市 + 日期范围 |
| `idx_date (monitor_date)` | 排行榜：同一日期全部城市快照；概览卡：最新一天 |

## 6. 数据获取与清洗规则（脚本：`db/` 目录）

### 6.1 获取（已落地：`db/download_data.py`）

- 数据源：`https://quotsoft.net/air/data/china_cities_YYYYMMDD.csv`（中国环境监测总站数据的镜像打包），2025 全年 365 个文件，保存于 `D:\airdata\raw\`，约 135 MB；
- 原始文件虽含小时数据，但天粒度的"日均值统计量"就在其中（`*_24h` 类型行），**无需其他来源**；
- 下载脚本支持断点续传、完整性校验、失败重试与失败清单（`failures.txt`）。

### 6.2 清洗（原型已验证：`db/extract_daily.py`，2025-01-15 实测 12/12 城提取成功）

对每个原始文件：

1. **只取 12 个目标城市列**；
2. **只取日报口径类型行**：`PM2.5_24h / PM10_24h / SO2_24h / NO2_24h / CO_24h / O3_8h_24h`，取当日最后一个非空小时的值（正常应为 23 时行；个别缺测时回退）；
3. **计算派生字段**：按 4.2 分段表计算各污染物 IAQI → AQI = max → `level`、`primary_pollutant`（规则见 4.1）；
4. **质量闸门**：某日原始文件有效小时数 < 12 → 该日整日丢弃（源头数据残缺时日均值不可靠）。**实测丢弃 4 天**：2025-06-04（4 小时）、06-15（9 小时）、06-28（9 小时）、11-06（10 小时）；
5. **缺失处理**：某城市当日 6 项统计量全部缺失 → 丢弃该行；部分缺失 → 用现有项计算（IAQI 取可见项的 max）。**实测城市-日空值丢弃 0 行**，12 城各 361 行完全齐平。

6. **自洽性约定**：AQI / 等级 / 首要污染物一律用**入库精度（取整后）的浓度**计算，而非原始浮点浓度。这样任何人从数据库或 CSV 复算都能得到完全一致的结果（`db/verify_task1.py` 的 E1 检查对 4,332 行逐行复算，偏差 0）。若改用浮点浓度计算，会有 ±1 的 AQI 偏差（实测 4 行）。

**实测结果（`db/import_report.txt`）**：

- 入库 4,332 行，12 城各 361 行；
- AQI：最小 13（深圳），最大 500（兰州/西安春季沙尘，PM10 爆表按国标封顶），均值 62.3；
- 六档等级全部出现：优 1906、良 1950、轻度 374、中度 59、重度 35、严重 8；
- 首要污染物分布：无 1906、O3 926、PM10 722、PM2.5 640、NO2 138。

## 7. 看板查询窗口映射（反推自三块图表需求）

| 看板区域 | 查询 | SQL 语义 |
|---|---|---|
| 概览卡 | 当前 AQI / 等级 / 首要污染物 | `WHERE city_id = ? AND monitor_date = (SELECT MAX(monitor_date) FROM air_quality)` |
| 趋势折线图 · 近 7 天 | 逐日 AQI | `WHERE city_id = ? AND monitor_date >= max_date − INTERVAL 7 DAY` |
| 趋势折线图 · 近 30 天 | 逐日 AQI | 同上，INTERVAL 30 DAY |
| 趋势折线图 · 近 12 个月 | 逐日 AQI | 同上，INTERVAL 12 MONTH |
| 排行榜 | 全城市同日快照 | `WHERE monitor_date = max_date ORDER BY aqi ASC` |

> 天粒度下所有查询都是索引直查，无需任何聚合，Service 层只剩等级换算与 DTO 组装。

## 11. 功能需求契约 A1~A4（2026-10-22 新增）

> 本节是 F1~F8 / A1~A4 需求的**唯一口径来源**。实现前先定死字段，避免前后端各写一份。

### 11.1 三个必须先定死的口径

**① 城市代码 = 现有 `city.id`（1~12）**

`city` 表不新增列。`cityCode` 只是响应层的字段名，值取 `id`。
理由：种子数据的 id 由 `init.sql` 固定写入，**可复现、可重跑**，当前阶段足够；
若将来要对外对接，只需改 Service 里的一行映射，接口签名与前端均不受影响。

**② 日期边界锁定 [2025-01-01, 2025-12-31]**

数据集的"今天"是 **2025-12-31**，不是系统当前日期（2026-10-22）。
因此前端日期控件必须设 `min=2025-01-01 / max=2025-12-31`，默认取 `[maxDate-29, maxDate]`；
否则用户一进页面就落在一段没有数据的区间上。
后端同样做**钳制**（超出数据集范围的起止日期收敛到边界），并校验 `start <= end`，否则 400。

**③ `level` 统一取"当天 AQI 等级"，不随 metric 变化**

指标切成 PM2.5 时，返回的是**这一天**的 AQI 等级，而不是 PM2.5 单独的 IAQI 等级。
理由：否则同一天同一城市，趋势图、排行榜、分布饼图会给出三个互相矛盾的等级。
等级换算仍走 `levelOf(aqi)`，与任务 11 的实现保持单一来源。

### 11.2 接口清单

```
A1  GET /api/cities
    → data: [{ code, name, province, region }]

A2  GET /api/air-quality?cityIds=1,2&metric=pm25&start=2025-01-01&end=2025-12-31&page=1&size=10
    → data: { total, page, size, list: [{ id, code, city, date, metric, value, unit, aqi, level, levelLabel }] }
    metric 取值: aqi | pm25 | pm10 | so2 | no2 | co | o3   （缺省 aqi）
    unit: μg/m³（CO 为 mg/m³，aqi 为空串）
    cityIds 为空 = 全部城市；page 从 1 起；size 上限 100

A3  GET /api/air-quality/stats?cityIds=&metric=&start=&end=
    → data: [{ code, city, metric, unit, avg, max, min, goodRatio, goodDays, samples, levelCounts }]
    goodRatio = level<=2（优+良）天数 / 有效天数 × 100，保留 1 位小数
    levelCounts = { 1: n, 2: n, ... 6: n }，支撑 F7 等级分布环形图

A4  GET /api/air-quality/{id}
    → data: { id, code, city, date, pm25, pm10, so2, no2, co, o3, aqi, primaryPollutant, level, levelLabel }
    id 不存在 → 404 标准错误体
```
